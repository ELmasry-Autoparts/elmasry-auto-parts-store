# وثيقة متطلبات المنتج (PRD)

## 1. ملخص المنتج

**اسم المنتج:** متجر عبدالرحمن المصري لتجارة قطع غيار السيارات الكورية.

**الهدف:** إطلاق واجهة تجارة إلكترونية عربية متخصصة في قطع الغيار الأصلية لسيارات هيونداي وكيا، بحيث يستطيع العميل الوصول إلى القطعة المناسبة بسرعة، ثم يرسل طلبه عبر واتساب بعد تأكيد المطابقة برقم الشاسيه (VIN).

**نطاق الإصدار الأول:** واجهة Shopify عربية باتجاه RTL. البحث برقم القطعة أو الوصف. محدد سيارة. فلترة حسب الماركة والموديل والجيل والسنة ونوع القطعة وموقعها. صفحات منتجات محسّنة لمحركات البحث. طلب أولي عبر واتساب. الدفع الإلكتروني والتكامل اللحظي مع ERP خارج النطاق الإجباري للإصدار الأول، لكن يجب ألا تمنع البنية إضافتهما لاحقًا.

> هذه الحزمة تحتوي على واجهة تجريبية تعمل ببيانات ثابتة، وقالبًا مرجعيًا لـ Shopify، ووثائق تنفيذ. لا تمثل المعاينة متجرًا متصلًا بكتالوج أو مخزون فعلي حتى يتم إدخال بيانات Shopify ومفاتيح الخدمات في بيئة آمنة.

## 2. المستخدمون والاحتياجات

| المستخدم | الحاجة الأساسية | معيار النجاح |
| --- | --- | --- |
| مالك السيارة | العثور على قطعة أصلية دون معرفة رقمها | الوصول إلى ترشيح أو محادثة واتساب خلال أقل من 3 خطوات |
| فني أو صاحب ورشة | البحث برقم OEM أو صورة/كود قطعة | ظهور رقم OEM والمصدر والمخزون بوضوح |
| فريق المبيعات | استلام طلب مفهوم وقابل للتنفيذ | رسالة واتساب تتضمن اسم المنتج ورقم OEM والموديل ورقم الشاسيه |
| مدير المخزن | منع بيع كمية غير متاحة | المخزون المنشور يطابق الموقع التجميعي ويمنع الطلب عند الصفر |
| مسؤول التسويق | جذب طلبات بحث محلية ذات نية شراء | صفحات موديلات وقطع قابلة للفهرسة مع بيانات محلية صحيحة |

## 3. الهوية والتجربة

الواجهة تستخدم وضعًا داكنًا فاخرًا بخلفية `#0B0E12` وسطح زجاجي شفاف. اللون الأساسي هو الأخضر النيون الهادئ `#89F36B` مع سماوي تقني `#5EE7ED`. التصميم يستخدم مساحات مريحة، بطاقات زجاجية، شبكة خلفية خفيفة، وحركة قصيرة لا تتجاوز 300ms. الخط الأساسي هو IBM Plex Sans Arabic، مع Space Grotesk للأكواد والأرقام اللاتينية.

اللغة العربية هي اللغة الأساسية. يجب ضبط `dir="rtl"` على مستوى المستند، مع إبقاء الأكواد وأرقام OEM وأرقام الهاتف باتجاه منطقي من اليسار إلى اليمين. يجب أن تظل الأزرار قابلة للاستخدام بلوحة المفاتيح وأن تحافظ على حلقة التركيز المرئية.

## 4. المتطلبات الوظيفية

### 4.1 التصفح والهوية

يعرض الهيدر اسم المتجر، رقم الهاتف، رابط واتساب، روابط السيارات والقطع والمساعد الذكي. يثبت الفوتر بيانات التواصل وموقع بلوك 11 الحرفيين – السلام – القاهرة. يجب أن يظهر زر واتساب عائم في الشاشات الصغيرة والكبيرة.

### 4.2 البحث

يدعم البحث النصي رقم OEM أو وصفًا بالعامية المصرية. في الإصدار الأول يمكن تنفيذ البحث عبر Shopify Search & Discovery وحقول المنتج. عند إضافة خدمة AI، يرسل الـ widget النص أو الصورة إلى Backend آمن، ولا يضع أي مفتاح API داخل Liquid أو JavaScript العام.

### 4.3 محدد السيارات

الخيارات الأولية هي توسان، إيلانترا، أكسنت، كريتا، سبورتاج، سيراتو، ريو، وسورينتو. كل موديل يرتبط بوسوم أو Metafields ثابتة تسمح باختيار الجيل والسنة وسعة المحرك. الضغط على بطاقة السيارة يوجه إلى مجموعة أو نتيجة بحث مفلترة.

### 4.4 الفلاتر

الهيكل المنطقي هو: الماركة، الموديل، السنة أو الجيل، مجموعة القطعة، ثم الفلاتر الخاصة. الحقول المقترحة تشمل سعة المحرك، المصدر، وموقع القطعة. لا ينبغي الاعتماد على النص الحر وحده؛ يجب حفظ القيم كـ product options أو metafields أو tags منظمة حتى تعمل الفلترة بلا تكرار.

### 4.5 المنتج

كل منتج يعرض عنوانًا موحدًا، صورة، حالة التوفر، المصدر، رقم OEM، موديلات التوافق، وسعرًا أو دعوة للاستفسار. يتم منع الطلب عندما تكون الكمية المتاحة صفرًا. زر واتساب يبني رسالة تتضمن المنتج ورقم OEM، ويطلب من العميل إرسال VIN قبل الشحن.

### 4.6 مساعد المصري الذكي

يتكون من ثلاث حالات واجهة: وصف القطعة، رقم OEM، ورفع صورة. النسخة التجريبية تعرض ترشيحًا محليًا ثابتًا. النسخة الإنتاجية تحتاج Backend يقوم بالتطبيع، واستخراج الكيانات، والبحث في كتالوج المنتجات، ثم إعادة نتائج مرتبة مع درجة ثقة. أي نتيجة منخفضة الثقة يجب أن تنقل العميل إلى مراجعة بشرية بدل اقتراح شراء مباشر.

## 6. قصص المستخدم ومعايير القبول

**كمالك سيارة** أريد كتابة «تيل فرامل قدامي لتوسان 2019» حتى أرى ترشيحًا مناسبًا أو أبدأ محادثة. معيار القبول هو أن تعرض الواجهة حالة نتيجة مفهومة، وأن تذكر أن المطابقة النهائية تتطلب VIN.

**كفني** أريد إدخال `58101-D3A00` حتى تظهر بطاقة المنتج التي تحتوي الرقم والمصدر والمخزون. معيار القبول هو عدم الخلط بين رقم OEM وSKU الداخلي.

**كمدير مخزن** أريد منع الطلب عند نفاد الكمية. معيار القبول هو أن تتحدث حالة المنتج إلى غير متوفر، وأن يمنع Shopify الإضافة أو الشراء وفق سياسة المخزون.

**كمسؤول تسويق** أريد صفحات موديلات قابلة للفهرسة. معيار القبول هو وجود عنوان ووصف فريدين، رابط داخلي واضح، بيانات منظمة، ونص مفيد لا يعتمد على JavaScript فقط.

## 7. القياس والتحليلات

يجب تسجيل أحداث: `search_submitted`, `vehicle_selected`, `filter_applied`, `matcher_started`, `matcher_result_viewed`, `whatsapp_clicked`, `product_viewed`, `add_to_cart`, و`checkout_started`. لا يتم إرسال VIN أو أي بيانات شخصية إلى تحليلات عامة. تُستخدم لوحات Shopify Analytics وGA4 أو أداة التحليلات المعتمدة بعد ضبط الموافقات والخصوصية.

## 8. الأداء وإتاحة الوصول

يجب ضغط صور السيارات بصيغة WebP أو AVIF عند توفرها، وتحديد أبعاد الصور لمنع اهتزاز التخطيط، وتأجيل الصور أسفل الطية. الهدف هو إبقاء JavaScript المخصص خفيفًا وتجنب استدعاء خدمة AI أثناء كل ضغطة مفتاح. يجب دعم لوحة المفاتيح، النص البديل، تباين النص، `prefers-reduced-motion`، وحالات الخطأ والفراغ.

## 9. خطة الإطلاق

يبدأ الإطلاق بكتالوج محدود ومراجعة يدوية للمخزون والأسعار. المرحلة الأولى هي عرض المنتجات واستقبال الطلبات عبر واتساب. بعد قياس البحث والطلبات، يضاف Paymob أو وسيلة الدفع المعتمدة مع الدفع عند الاستلام. بعد استقرار الكتالوج، يتم تشغيل مزامنة ERP وتفعيل بحث الصور والذكاء الاصطناعي.

## 10. المخاطر والضوابط

الخطر الأكبر هو ترشيح قطعة غير متوافقة. الضابط هو إبراز أن VIN إلزامي للمطابقة، وإظهار درجة الثقة، وعدم السماح للمساعد بتأكيد الطلب وحده. خطر آخر هو ادعاء الاعتماد أو الأصالة دون مستندات. لذلك يجب ربط الشارات بمصدر موثق داخل بيانات المنتج ومراجعة قانونية قبل نشر عبارة «موزع معتمد».

## 11. مخرجات هذه الحزمة

يتضمن المشروع واجهة React تجريبية قابلة للمعاينة، وملفات Liquid/CSS/JavaScript مرجعية، وخطة ERP/Supabase، ومحتوى SEO عربي. الملفات لا تتصل تلقائيًا بحساب Shopify الحالي ولا تنشئ منتجات أو تغير مخزونًا؛ هذه خطوات تشغيلية تتطلب اعتماد بيانات الكتالوج وخطة صلاحيات واضحة.
